### 其他觀察

- B 的 renderer 參數（字級 11/14/19/22px、按鈕 52px、mega 寬 300）都是憑記憶填的，自己也註明「沒有對照官方文件確認」。這次全部猜對，唯一猜錯的是行高（它假設約 20px，實機是 16.8px）。
- A 在使用過程中找到 `shrink-to-fit` 的兩個 renderer bug：`scrollWidth` 取整數造成誤判、按鈕量錯元素。兩個都已修正。
- B 沒有 token，無法實際驗證 LINE 是否接受；A 有 Validate API 給出確定的結果。

## 結論

- 不用 skill 時，模型本身就能寫出合法、版面定性正確的 Flex，常見的截斷和換行結果也預測得到。
- skill 實際測得出的優勢：
  1. 用 Validate API 確實驗證，而不是推測。
  2. 垂直尺寸的準確度：行高是校正過的。不用 skill 的話，文字多的卡片會高估 10–15%。
  3. 有現成、經過測試的工具，不必每次臨時搭建，所以比較快。
  4. 有 `--boxes` 座標、完整的 carousel 預覽，以及常見陷阱清單。
- 價格縮放這類水平方向的數值，兩組都有 ±2px 的誤差，差距不明顯。
